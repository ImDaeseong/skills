# 사용법

## 언제 사용하는가

목차와 장 사이의 논리 연결이 중요한 논픽션, 기술서, 전자책처럼 긴 원고에 사용한다. 짧은 글 한 편, 이미 확정된 문장의 교정, 단순 요약에는 이 절차를 적용하지 않는다.

## 준비물과 폴더

```text
book-project/
├── outline.json
├── evidence/
├── manuscript/
└── review-notes.md
```

- `outline.json`: 두 모델이 함께 따르는 구조 계약
- `evidence/`: 사용자가 제공하거나 사용을 승인한 근거
- `manuscript/`: Claude가 작성하는 `NN_slug.md` 파일
- `review-notes.md`: 승인 버전, 변경 이유, 남은 TODO와 출간 HOLD

## 1. ChatGPT에서 구조 만들기

```text
structure-to-manuscript 스킬을 사용해 이 책의 구조 레이어만 작성해 줘.
독자: [대상]
중심 문제: [한 문장]
완독 후 결과: [한 문장]
분량과 문체: [조건]
사용 가능한 근거: [파일 또는 출처 범위]
아직 원고를 쓰지 말고 outline.json과 HOLD만 보여 줘.
```

목차, 장별 목표, 핵심 주장, 의존관계, 용어와 근거 요구 사항을 검토한다. 마지막 장에는 `resolves_promise: true`가 있어야 한다. 사용자가 구조를 승인한 뒤 `outline.json`을 고정한다.

## 2. Claude에 인계하기

승인된 `outline.json`, 허용된 근거, 기존 문체와 변경 금지 범위, `review-notes.md`를 함께 전달한다. 비공개 원고를 외부 서비스로 전달하기 전에는 데이터 범위와 사용자의 승인을 확인한다.

```text
첨부한 outline.json을 집필 계약으로 사용해 줘.
먼저 계약의 필수 필드, 의존관계, 근거 누락과 마지막 장의 약속 회수 여부를 검사해.
문제가 있으면 원고를 쓰지 말고 HOLD를 보고해.
문제가 없으면 장별로 manuscript/NN_slug.md를 작성해.
구조에 없는 핵심 주장은 임의로 추가하지 말고 변경 제안으로 돌려줘.
확인되지 않은 사실은 [TODO: 필요한 근거]로 남겨.
```

ChatGPT와 Claude를 실제로 연결하는 자동 API는 포함하지 않는다. 파일을 직접 전달하거나 사용자가 승인한 통합 환경에서 인계한다. 한 모델만 쓸 때도 구조 작성 세션과 집필 세션을 분리하고 승인 게이트를 유지한다.

## 3. 검사하기

스킬 폴더의 검사기를 책 프로젝트에서 실행한다.

```text
python path/to/structure-to-manuscript/scripts/check_consistency.py outline.json manuscript/
```

`PASS STRUCTURE_TO_MANUSCRIPT_CONSISTENCY`는 파일 구조, 의존관계, 금지 용어, 분량 편차와 TODO에 대한 기계적 검사 통과를 뜻한다. 주장 간 모순, 사실성, 문장 품질과 출간 승인을 뜻하지 않는다.

검사 실패 시 진단된 항목만 수정하고 다시 실행한다. 구조에 영향을 주는 변경이면 집필 중에 직접 고치지 않고 ChatGPT 구조 레이어로 되돌려 `outline.json`을 재승인한다.

## 4. 사람 검토와 종료

1. 모든 핵심 주장이 본문에서 설명됐는가
2. 뒤 장이 앞 장의 전제와 충돌하지 않는가
3. 근거와 사례가 주장을 뒷받침하는가
4. 마지막 장이 책의 약속을 의미상 회수하는가
5. TODO와 출간 HOLD가 숨겨지지 않았는가

기계 검사 PASS와 사람 검토가 모두 끝나면 원고 단계를 완료한다. 외부 근거 확인, 교정, 유통 메타데이터와 판매 파일 검수는 별도의 출간 게이트로 관리한다.
