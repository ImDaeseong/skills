# Structure to Manuscript

## 공통 규칙

Follow `../_shared/CORE-LAWS.md` in full.

## 핵심 역할

- **ChatGPT는 아이디어·구조 레이어를 담당한다.** 독자의 문제를 명확히 하고, 책의 약속·논리 순서·챕터 목표·핵심 주장·의존관계·용어를 `outline.json`으로 고정한다.
- **Claude는 글쓰기 레이어를 담당한다.** 승인된 `outline.json`을 집필 계약으로 사용해 각 챕터를 완전한 원고로 바꾸고, 처음부터 끝까지 주장·용어·연결이 일관되게 만든다.

사용자가 다른 모델을 지정하면 그 선택을 따른다. 중요한 불변 조건은 두 역할의 분리와 고정된 인계물이다. 같은 모델이 두 역할을 수행할 때도 구조 승인 전에는 집필로 넘어가지 않는다.

구체적인 준비물, 프롬프트, 폴더 구성과 명령은 `references/usage.md`를 따른다.

## 시작 전 확인

이미 주어진 정보는 다시 묻지 않는다. 다음 중 결과를 크게 바꾸는 항목만 확인한다.

1. 독자와 현재 상태
2. 책이 해결할 단 하나의 중심 문제
3. 완독 후 독자가 할 수 있어야 하는 일
4. 분량, 문체, 출판 형식
5. 사용할 근거 자료와 인용 정책

문제가 여러 개면 중심 문제 하나와 보조 문제로 구조화한다. 문제를 임의로 좁혀 사용자의 의도를 바꾸지 않는다.

## 1. 구조 레이어 — ChatGPT

`references/outline-schema.md`를 읽고 `outline.json`을 만든다.

- 각 챕터에 `goal`, `key_claims`, `depends_on`, `examples`, `target_words`를 둔다.
- 책 전체의 표준 용어와 금지 변형을 glossary에 기록한다.
- 주장에 필요한 근거가 없으면 출처를 지어내지 않고 `evidence_needed`에 남긴다.
- 마지막 챕터가 책의 약속을 회수하도록 설계하고 `resolves_promise: true`로 명시한다.
- 구조를 사용자에게 보여 주고 명시적 승인을 받는다.

승인 전에는 완성 원고를 작성하지 않는다. 구조 수정 비용이 원고 전체 재작성 비용보다 작기 때문이다.

## 2. 인계 게이트

ChatGPT의 결과를 Claude에게 전달할 때 다음 파일을 한 묶음으로 사용한다.

- `outline.json`: 구조의 정본
- 사용자가 제공한 근거 자료 또는 허용된 출처 목록
- 기존 원고가 있으면 변경 금지 범위와 유지할 문체
- 승인 기록: 승인된 버전과 남은 HOLD

Claude는 인계물을 먼저 검사한다. 필수 필드 누락, 잘못된 의존관계, 근거 없는 핵심 주장, 약속과 마지막 챕터의 불일치가 있으면 집필을 시작하지 않고 구조 레이어로 되돌린다.

## 3. 글쓰기 레이어 — Claude

챕터를 순서대로 `manuscript/NN_slug.md`에 작성한다.

- 해당 챕터의 목표와 핵심 주장만 확립한다.
- 선행 챕터에서 이미 확립한 주장은 반복 설명보다 필요한 만큼 참조한다.
- 첫 부분에서 챕터의 질문을 열고 마지막 부분에서 다음 챕터의 필요성을 연결한다.
- glossary 표준 표기를 유지한다.
- 구조에 없는 새 핵심 주장이 필요하면 조용히 추가하지 않고 `outline.json` 변경을 제안한다.
- 확인되지 않은 수치·인용·사례는 만들지 않고 `[TODO: 필요한 근거]`로 표시한다.

문장 품질뿐 아니라 책 전체의 논리 연결을 책임진다. 앞 장의 전제와 충돌하거나 책의 약속 범위를 넓히는 문장을 발견하면 해당 챕터만 고치기 전에 구조 계약을 확인한다.

## 4. 검증 레이어

기계적 검사는 다음 명령으로 실행한다.

```text
python scripts/check_consistency.py outline.json manuscript/
```

검사는 챕터 누락·여분, 구조 필드, 의존관계, 용어 변형, 분량 편차와 TODO를 확인한다. 그 뒤 사람이 다음을 검토한다.

- 각 `key_claims`가 실제 본문에서 설명되었는가
- 뒤 챕터가 앞 챕터의 전제와 모순되지 않는가
- 사례가 주장을 실제로 뒷받침하는가
- 마지막 챕터가 처음 약속을 이행하는가
- 확인하지 못한 사실과 출간 HOLD가 남아 있는가

자동 검사는 의미적 모순, 사실성, 독자 경험 또는 출간 승인을 보장하지 않는다.

## 안전 경계

- 이 스킬은 외부 모델 API를 자동 호출하지 않는다.
- 원고·비공개 자료를 다른 모델이나 서비스로 보내기 전에 사용자 승인과 데이터 범위를 확인한다.
- 모델명·가격·플랫폼 정책을 소스에 하드코딩하지 않는다.
- 의료·법률·금융처럼 고위험 사실이 포함되면 전문가 검토를 HOLD로 남긴다.

## 완료 조건

- 승인된 `outline.json`이 있다.
- 모든 챕터 파일이 구조와 일치한다.
- 기계적 검사가 PASS다.
- 논리 검토 결과와 수정 내역이 기록됐다.
- 남은 TODO와 출간 HOLD가 숨겨지지 않았다.
